# 結果導向執行

針對預期且可驗證的最終狀態進行最佳化，而非保留平滑的中間狀態。

**原因：** 保持每個中間步驟完全穩定，常會產生暫時的相容性程式碼，最終成為長期負債。聚焦於目標架構，並在明確的驗證界限上證明正確性。

**核心規則：**
- 優先考慮最終狀態的完整性，而非過渡穩定性
- 中間破壞是可接受的，當它是規劃的、範圍明確且可回復的

**護欄：**
- 在規劃的重寫和遷移中使用此方法，並明確的階段界限
- 明確宣告暫時破壞可接受的範圍
- 在遷移期間，對積極處理的區域保留高訊號檢查
- 在計畫完成時，要求完整的靜態和執行驗證
