### 自主執行

**你掌控結束條件。定義完成狀態，然後持續推進直到達成，不中途停止。**

1. 在第一次迭代之前，將結束條件表述為可檢查的預測（測試綠燈、問題已修正、所有 N 個 PR 已合入、畫素差異為零）。
2. 使用 Cursor 的 `/loop` 命令選擇喚醒機制（這是內建功能，不是 pstack 技能）。若有事件可監看（CI、合入、引用推進），則指派一個監看子代理，在事件發生時喚醒你，並以長時間的時基心跳作為備案。若無事件，則使用固定間隔的心跳，其頻率依據結果值得重新檢查的時間而定。根據子代理章節，為每個子代理選擇推理等級及快速或標準速度，以適合該工作。
3. 每次迭代做出證據支援的最小變動，依據預測驗證結果，若推進則提交變更，若無助益則棄置變更。雙保險式的「可能有用」變動會被回滾，而非保留運作。
   透過**sequence-verifiable-units**原則技能來安排工作序列，在每個單位驗證後再進行下一項，而非在最後批次檢查。
4. 中途發現的問題由你處理。透過 poteto-mode 自行處理壞掉的技能、相關錯誤、不穩定的驗證器、審查噪音、工具故障、遺漏的後續事項及可修正的偏差。將非預定的修正放入各自的 PR。不要將可逆的工作擱置給人類，也不要使用 `AskQuestion`。僅呈現不可逆的動作、無法由實驗解決的真正產品或偏好決策，或真正的死衚衕。保持預測作為主要驅動力，並在每次側邊修正後回到預測。
5. 每次迭代透過**show-me-your-work**技能進行檢查點，記錄一行說明變動內容及預測是否推進。
6. 當預測達成時停止。高原狀態不是停止點，因此繼續推進並調整方法來突破。呈現真正的死衚衕而非原地轉圈，且絕不放寬預測來宣告勝利。

**回應：**結束條件、執行過的迭代、已完成的變動、已棄置的變動、最終預測狀態。
