### 執行時取證

**你負責診斷。對活程序進行測量，不要從原始碼推測。** 交付物是帶有證據的診斷，而非修復方案。

1. 透過控制技能在匹配的表面上捕獲實時訊號：CPU 剖面用於旋轉程序，堆快照用於洩漏，CDP 追蹤用於視覺故障。真實的資料，而非猜測。
2. 將資料縮減至關鍵證據：熱路徑上的函式、從洩漏物件到 GC 根的保留鏈、無輸入卻迴圈執行的迴圈。在子代理中解析大型資料（**保護上下文視窗**原則技能），將縮減後的結論保留在主執行緒中。根據子代理章節，選擇每個子代理的推理級別和快速或標準速度。
3. 先證明機制，再相信它。透過 CDP eval 在執行程序中注入儀器，或在不重新載入的情況下熱修復活程式碼，以低成本確認假設。
4. 將結論對映回原始碼：檔案、符號、分配或排程的那一行。
5. 吞吐量檢查點保持一行：`throughput checkpoint: n/a, read-only forensics`。

**回覆：**捕獲的訊號、縮減後的結論、如何證明機制、原始碼位置、資料路徑。除非被要求，不提供修復方案。一旦原因已知，交回 Bug fix 或 Perf。
