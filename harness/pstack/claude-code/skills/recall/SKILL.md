# 回想

In Claude Code, read [the Claude Code adapter](../../docs/harness/claude-code.md) once per session before you follow this skill. It maps the Cursor names in pstack skills to Claude Code.

**在你開始或恢復工作之前，你重建使用者最近的工作情境，並回傳一份精簡摘要，說明目前狀態與下一步該做的事。**

保持精簡且聚焦主題。只讀取範圍內相關執行緒所需的內容，然後停止。

你的情境存在於兩個記錄中。你自己的聊天歷史記錄了你做了什麼和決定什麼。共享記錄記錄了同一程式碼在其他名稱下發生的一切：使用者持續報告的症狀、已發布又被撤回的修正、仍在生產環境中觸發的錯誤。第二個記錄正是 **why** 技能所搜尋的範圍，橫跨版本控制系統、問題追蹤器、聊天與問題通道、長篇文件和錯誤追蹤。一個有長錯誤尾巴的功能，大部分故事都在那裡，所以不要僅從你的對話記錄來重建它。

對話記錄位於 `~/.cursor/projects/<slug>/agent-transcripts/<uuid>/<uuid>.jsonl`，其中 `<slug>` 是工作區路徑，去掉前導斜線，並將每個「/」轉為「-」（因此 `/Users/you/proj` 變成 `Users-you-proj`）。每一行是一條聊天訊息。

1. 分類，然後分流。一個特定的先前聊天要恢復是 `session-pickup` 的劇本，不是這個。將習慣轉為持久技能是 `automate-me`。人類可讀的工作摘要是另一個任務。回想是在你行動之前，跨最近的聊天載入工作情境。如果使用者已經給你完整的狀態摘要（路徑、分支、變更），直接使用它並跳過挖掘。
2. 先鎖定範圍再搜尋。確定時間視窗（「最近」是實際範圍，預設為過去 7 天）、主題（若已命名）和工作區（預設為當前活動工作區。除非被要求，絕不讀其他專案的對話記錄）。回報範圍。絕不靜默將「全部」變成「最近 N 個」。
3. 在你的聊天歷史中展開搜尋。在快速且便宜的模型上啟動平行子代理，每個負責一部分資料集。告訴每個子代理按實際修改時間（`ls -t`）排序候選，絕不按 UUID 名稱排序，先 grep 主題，然後只讀匹配的聊天及其相關區域，並跳過當前聊天和明顯的噪音（子代理、評估和測試聊天）。每個回傳相同的結構，每個聊天一個區塊：主題、使用者目標、決策、未解決執行緒、困難與修正、以及產出（PR、票證、分支），每個都引用聊天 UUID。對於一或兩個聊天，跳過展開並直接搜尋。原始對話記錄留在子代理中。主執行緒只收到他們的結果。根據 **poteto-mode** 技能的 Subagents 章節，選擇每個子代理的推理等級和快速或標準速度。
4. 當主題命名一個功能、檔案、子系統、區域或錯誤時，掃描共享記錄。這是預設，不是判斷性決定，且「我在 X 上的工作」並不豁免。交給 **why** 技能的來源調查者，但將他們的問題從「為什麼這樣建」轉為「當前狀態是什麼、什麼已被嘗試但未能維持、使用者仍在報告什麼」。重用其各來源的劇本，在聊天歷史挖掘的平行中執行調查者，並沿用其立場：每個來源一個調查者、空結果是結果、跳過不可用的 MCP 並說明。將回傳結果整合進摘要。僅在純活動回想且沒有命名目標（「我這週做了什麼」）時跳過此步驟，此時你自己的歷史和當前狀態就是完整答案。
5. 對當前狀態進行驗證。取挖掘和掃描所產出的 PR、分支和票證，用 `git` 和 `gh` 檢查。當答案取決於代理實際做了什麼（它執行的工具、讀的檔案、遇到的錯誤），讀完整對話記錄，而不是僅修剪的本地副本。
6. 將摘要寫入以下契約。按執行緒分組。保持在命名主題上。

<a id="output-contract"></a>

## 輸出契約

先以摘要開頭，然後執行緒狀態，然後問題，然後下一步行動。更深的細節放在下方或被刪除。

- **摘要。** 最多 5 個專案。這項工作是什麼及其整體狀態。
- **執行緒。** 每個一行，字首恰好一個狀態標籤：`[merged #N]`、`[open PR #N]`、`[in flight <branch>]`、`[verified, uncommitted]`、`[reverted #N]` 或 `[planned, not started]`。沒有標籤的執行緒尚未完成，所以請標上標籤。
- **問題。** 最多 5 個，常見的。包括使用者持續報告的症狀和任何已發布又被撤回的修正，讓下一次嘗試從上次失敗之處開始。
- **下一步行動。** 單一最有用的下一步行動，具體明確。

相關的功能或票證除非阻礙此項，否則不列入。當摘要和執行緒行超過一個螢幕時，先刪細節再刪執行緒。透過 **unslop** 技能寫摘要，聊天結果引用 UUID，共享記錄結果引用來源（PR 號、票證 ID、聊天永久連結、錯誤追蹤器問題），並在任何公開輸出前清理私人情境。

**回覆：** 摘要，符合上述契約。
