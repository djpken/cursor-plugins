# 將工作序列化為可驗證的單位

將工作組織為一系列小單位，每個單位以可檢查的狀態結束，並且在當前單位綠燈之前不要推進。

**原因：** 在導致問題的單位處捕捉到的故障很容易定位。批次後捕捉到的故障會被埋藏，並且你已經在故障基礎上進一步構建。將這些相同單位序列化為審閱者可以重播的交付，將「相信我」變成「看著它變紅，然後變綠」。

**執行。** 在掃描、遷移或任何一系列相似編輯中，在開始下一項之前驗證每個更改。每個單位是一個前/後括號：已知良好狀態、一個更改、執行檢查，然後繼續。首先重新基於乾淨的主幹，以便每個檢查都針對真實基準進行衡量。當一個工具進行編輯時，每個單位檢查幾乎是免費的。仍然執行它。

**交付。** 按照證明工作的順序堆疊提交和 PR。典型形態是先有失敗測試，然後在其上進行修復。其他故事順序包括重塑前的減法、治療前的基準捕捉、功能前的腳手架。每個提交獨立落地，序列讀起來像一個論證。

這是**證明它工作**原則技能的序列補充，該技能確保每個檢查真實，以及**建立槓桿**原則技能，該技能使每個單位檢查便宜。
